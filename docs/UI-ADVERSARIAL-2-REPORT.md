# BudsDock UI两轮对抗审查报告

> 历史记录：本文记录2026年7月26日早期实现状态，其中部分结论已失效。当前实现与验收要求以`docs/DESIGN.md`和`docs/TESTING.md`为准。

日期：2026年7月26日

## 审查目标

本轮审查聚焦以下问题：

1. Dock和设置页的视觉美观度、空间层级、深浅主题一致性。
2. 图标、底片、单色图标和内置备用图标的可识别性与对比度。
3. 鼠标悬停后的放大、相邻缩放、发光、倒影、命中区和状态清理。
4. 主题切换、关闭动画、全屏隐藏和鼠标穿透切换后的运行时稳定性。

## 第一轮发现与处理

### 已修复

- 悬停缩放从Dock项目外层移动到固定尺寸的IconVisual，避免布局尺寸和图标按钮命中区随放大改变。
- 发光BlurRadius改为随IconSize联动，范围7～28px，小图标不再被固定22px光晕吞没。
- 悬停状态增加延迟合并，鼠标从一个图标快速移动到另一个图标时不再先全部回缩再放大。
- 增加Window级MouseLeave处理，补充全屏隐藏、全屏恢复和鼠标穿透切换时的hover清理。
- 倒影只在横向Dock显示，倒影高度按图标尺寸的26％计算，纵向Dock和关闭倒影时不再保留空白行。
- 纯视觉层设置为不可命中，图标按钮成为唯一启动和命中入口，点击倒影不会误触发拖动。
- 内置图标增加主题前景色资源和字体回退链。
- Light主题Accent调整为`#3E5BC2`，IconTile调整为`#B9C6E0`，IconForeground调整为`#202431`。
- Dark主题内置备用图标采用更深的底色，降低白色字形与底色之间的对比度风险。
- 内置图标单色模式使用透明字形蒙版，避免把完整的彩色圆角底片当作单色轮廓。
- Dock背景主题颜色改为不带Alpha的表面颜色，用户设置的BackgroundOpacity成为唯一透明度变量；默认值调整为88％，兼顾参考图的半透明质感与壁纸变化时的图标可识别性。
- 设置页按钮禁用态不再通过整体Opacity压低文字，新增自定义ToolTip、ListBox选中强调条、Slider、ComboBox和ComboBoxItem主题模板。
- Light主题DangerButton颜色调整为`#A33D4B`，普通字号下与浅色表面达到4.5:1以上对比度。
- 恢复交互快捷键和托盘菜单只恢复Dock交互，不再强制弹出设置窗口。
- 悬停状态不触发配置写盘，避免快速扫过图标产生无意义的磁盘I/O。

### 审查中的科学性修正

- `OpacityMask`中的白色只影响Alpha，不作为白色倒影绘制色；第一轮中将其误判为白色倒影的结论已撤回。
- Tile底片属于低对比度装饰层，不直接套用普通文本4.5:1标准；如果将其作为唯一按钮边界，则应按非文本组件3:1标准继续验收。
- Original图标来自用户提供的EXE、LNK或图片文件，无法用单一主题颜色证明所有输入均达到统一对比度，因此保留“输入依赖”边界。
- Monochrome实际使用AccentBrush，不使用IconForegroundBrush；对比度应按Accent与Dock实际合成背景计算。

## 第二轮复核结果

第二轮重点复核了：

- 悬停缩放是否仍参与按钮命中。
- 动态BlurRadius是否随尺寸变化。
- 倒影行在纵向和关闭状态是否收缩为0。
- 悬停状态是否能在全屏、鼠标穿透、设置切换后清理。
- 主题资源替换是否能刷新内置图标缓存。
- 浅色主题DangerButton、Slider、ComboBox和ToolTip是否存在系统色残留。

复核结论：第一轮提出的主线视觉和交互问题已修复。当前保留的产品边界主要是Original模式图标本身由外部文件决定，以及极端高亮壁纸下半透明Dock仍需要真实桌面截图进行验收。当前默认Dock表面透明度已提高到88％，这会显著降低该风险，但无法对任意壁纸和任意外部图标做绝对保证。

## 自动化验收

当前测试套共10项，全部通过：

- 横向和纵向排列。
- 底部和屏幕中心定位。
- 主屏工作区Clamp。
- 设置值边界。
- 默认内置项目。
- `.budsdock`配置包和自定义图标恢复。
- 导入前恢复副本。
- 中英文资源键一致性。
- Light/Dark主题图标前景、底片、Accent和危险文字对比度Token检查。

开发版设置页启动冒烟测试通过，发布版重新打包后还需再次执行同样验证。

## 推荐手工验收矩阵

- Dark、Light主题各测试Original、Tile、Monochrome。
- IconSize测试28、54、112px。
- DockScale测试0.65、1.0、1.8。
- GlowIntensity测试0、0.34、1.0。
- 测试第一个、中间和最后一个图标。
- 使用纯黑、纯白、浅灰、深灰和高饱和壁纸观察对比度。
- 快速从图标A划到图标B，再离开Dock，确认没有回缩抖动和放大残留。
- 切换鼠标穿透、全屏隐藏、关闭悬停动画和深浅主题，确认图标状态立即恢复。

## 结论

BudsDock当前版本达到Beta交付标准。视觉方向保持参考图的低干扰悬浮感，图标可识别性、主题科学性和悬停交互已完成两轮对抗修复。Original模式的最终效果仍受外部图标文件本身影响，正式发布前应补充真实桌面壁纸和常用应用图标的截图验收。
