# BudsDock 1.0.2验收说明

1.0.2修复从全屏应用返回桌面或普通窗口后，Dock延迟出现、偶发持续消失的问题。

## 原因与修复

1.0.1仅每1.5秒检查一次全屏状态。退出全屏后需要等待下一次轮询，界面线程忙碌时还会继续延迟。

原恢复条件仅识别程序主动全屏隐藏时设置的标记。Windows将Dock最小化、隐藏底层窗口或改变置顶状态时，这个标记可能没有变化；即使再次调用WPF的`Show()`，窗口也可能仍处于最小化状态。重新赋予相同的`Topmost`值，也不能保证Windows底层层级恢复。

修复后，前台窗口切换、最小化、窗口移动缩放结束和桌面切换通过`SetWinEventHook`触发检查；通知合并后在窗口线程执行，退出时解除钩子。500毫秒的正常优先级定时器作为兜底，关闭全屏避让后仍检查系统最小化与可见性。

恢复时核对Windows实际可见性与最小化状态，通过`SW_SHOWNOACTIVATE`恢复窗口，并按设置修复原生置顶状态。自动恢复不会激活Dock。全屏窗口所属显示器依据保存的显示器选择判断，避免Dock被最小化后临时坐标改变判断结果。切换过程中前台窗口句柄暂时为空时，保留上次可见状态，等待后续事件或兜底检查。

这些缺失的恢复路径可以在窗口测试中复现。系统负载会影响消息处理速度，但持续不恢复也与窗口状态处理缺失有关。

## 验证结果

验证环境为Windows 11 x64，.NET 10 SDK 10.0.302。基础回归测试45项全部通过，Release构建无错误、无警告。

12项真实WPF／Win32窗口测试全部通过：

1. 未设置全屏隐藏标记时，系统最小化后恢复，且保留原前台窗口焦点。
2. 关闭全屏避让后，仍能从系统最小化恢复。
3. WPF仍认为窗口可见、Windows底层窗口已隐藏时恢复。
4. 原生置顶状态丢失后修复。
5. 非置顶设置在最小化恢复后保持。
6. 手动恢复交互路径解除最小化。
7. 前台全屏进入时响应窗口事件。
8. 退出全屏后恢复，且不抢占全屏应用焦点。
9. 连续50次全屏窗口最小化并返回普通测试窗口后恢复。
10. 界面线程阻塞1.8秒，恢复消息处理后重新显示。
11. 全屏期间被最小化时继续避让，退出后解除最小化。
12. 全屏期间关闭避让设置，立即恢复Dock。

Portable与Compact分别通过深色中文960×680、浅色英文640×480的发行包检查；搜索隔离、排序、300个并发图标加载和缓存上限均通过，WPF绑定错误日志为空。

窗口测试包含真实跨进程全屏窗口、最小化与普通窗口切换，不等同于覆盖所有Windows桌面操作。独占全屏游戏、不同显卡和混合DPI多显示器组合需要在对应设备验证。自动恢复仍依赖窗口线程能处理消息；无法在该线程持续阻塞时保证立即显示。

## 升级

退出旧版，解压新版并运行`BudsDock.exe`。配置继续使用`%LocalAppData%\BudsDock`，没有配置格式迁移；已有图标、外观与位置保留。移动安装目录后，运行一次新版可按原有设置刷新开机启动路径。

Portable包含.NET 10.0.14；Compact使用本机.NET 10 Desktop Runtime x64。发行包的精确大小与SHA-256见`outputs`中的JSON和SHA256文件。

## Windows接口依据

- [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)：事件范围、线程消息循环和钩子生命周期。
- [ShowWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow)：`SW_SHOWNOACTIVATE`的窗口恢复与焦点行为。
